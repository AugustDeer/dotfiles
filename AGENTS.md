# AGENTS.md

Personal NixOS flake (flake-parts + import-tree) for one host (`augustROG`) and one user (`adeer`). No CI; verify changes by evaluating/building.

**Never commit changes or run any activation command (`nixos-rebuild`, `home-manager switch`) without explicit confirmation from the user.**

## Module system (non-obvious)

- `flake.nix` builds outputs via `inputs.import-tree ./modules`: **every `.nix` file under `modules/` is auto-imported as a flake-parts module** — new files need no registration. Any path containing `/_` is silently skipped (this is why `_hardware-configuration.nix` is prefixed with `_` and imported manually).
- Files in `modules/` are flake-parts modules (arguments like `inputs`, `flake`, `perSystem`, `withSystem`), not plain NixOS modules. Outputs are declared as `flake.nixosModules.*`, `flake.homeModules.*`, `perSystem.packages.*`.
- Layout: `modules/hosts/<host>/` — system config (one per machine); `modules/user/` — home-manager config; `modules/formatter.nix` — formatter.

## Build & deploy

- Two separate activations — home-manager is **not** integrated into the NixOS config (no `home-manager.users.adeer`):
  - System: `sudo nixos-rebuild switch --flake .#augustROG`
  - Home: `home-manager switch --flake .#adeer`
- Test without deploying: `nix build .#nixosConfigurations.augustROG.config.system.build.toplevel` and `nix build .#homeConfigurations.adeer.activationPackage`.
- Format with `nix fmt` (treefmt + nixfmt).
- Neovim is built with nvf as `perSystem.packages.neovim` and pulled cross-system via `withSystem` in `modules/user/nvim.nix`; test with `nix build .#neovim`.

## Conventions

- All flake inputs follow `nixpkgs` (nixos-unstable); keep that pattern when adding inputs.
- Do not edit `_hardware-configuration.nix` (generated by `nixos-generate-config`) or bump `system.stateVersion` / `home.stateVersion` (26.05).
- Machine-specific values live in the host module: NVIDIA PRIME bus IDs, LUKS UUIDs, `nixos-hardware` module list, and mango monitor rules.
- Commit messages follow conventional style (`feat:`, `fix:`, `refactor:`).
