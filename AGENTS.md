# AGENTS.md

Personal NixOS flake (flake-parts + import-tree, dendritic layout) for one host (`augustROG`) and one user (`adeer`). No CI; verify changes by evaluating/building.

**Never commit changes or run any activation command (`nixos-rebuild`, `home-manager switch`) without explicit confirmation from the user.**

## Module system (non-obvious)

- `flake.nix` builds outputs via `inputs.import-tree ./modules`: **every `.nix` file under `modules/` is auto-imported as a flake-parts module** — new files need no registration. Any path containing `/_` is silently skipped (this is why `_hardware-configuration.nix` is prefixed with `_` and imported manually).
- Files in `modules/` are flake-parts modules (arguments like `inputs`, `config`, `lib`, `withSystem`, `perSystem`), not plain NixOS modules. Modules that need no arguments are written as bare attribute sets.
- Outputs are declared as `flake.modules.<class>.<aspect>` (`class` is `nixos` or `homeManager`), plus `perSystem.packages.*`. The `flake.modules` option comes from `modules/flake/flake-parts.nix`; `flake.homeConfigurations`/`flake.homeModules` from `modules/flake/home-manager.nix`.
- Aspects reference each other through `config.flake.modules.<class>.<aspect>`; avoid relative `import` paths between modules (the generated `_hardware-configuration.nix` is the one exception).
- A file may define aspects for several classes — e.g. `modules/programs/mango.nix` provides both `flake.modules.nixos.mango` and `flake.modules.homeManager.mango`.

## Layout

- `modules/flake/` — flake-parts plumbing: `systems`, `formatter`, and the flake-module imports.
- `modules/programs/` — home-manager aspects (per-program config for `adeer`).
- `modules/system/` — reusable NixOS aspects.
- `modules/hosts/<host>/` — host composition (`default.nix`) and machine-specific hardware (`hardware.nix`); `_hardware-configuration.nix` is generated.
- `modules/users/` — home-manager user composition (`adeer.nix`).
- `modules/theme.nix` — cross-cutting color theme (Kanagawa) shared across programs.

## Build & deploy

- Two separate activations — home-manager is **not** integrated into the NixOS config (no `home-manager.users.adeer`):
  - System: `sudo nixos-rebuild switch --flake .#augustROG`
  - Home: `home-manager switch --flake .#adeer`
- Test without deploying: `nix build .#nixosConfigurations.augustROG.config.system.build.toplevel` and `nix build .#homeConfigurations.adeer.activationPackage`.
- Verify a refactor is behavior-preserving by comparing derivations: `nix eval --raw .#<attr>.drvPath`. A home-manager top-level drv hash can change on package reordering, so compare generated files instead: `readlink -f "$(nix build .#homeConfigurations.adeer.activationPackage --no-link --print-out-paths)/home-files"`, and/or `nix store diff-closures <old> <new>`. Stage new files (`git add`) first — flakes ignore untracked files.
- Format with `nix fmt` (treefmt + nixfmt).
- Neovim is built with nvf as `perSystem.packages.neovim` (`modules/programs/nvim.nix`) and installed via `home.packages` in `modules/programs/cli.nix`; test with `nix build .#neovim`.

## Conventions

- All flake inputs follow `nixpkgs` (nixos-unstable); keep that pattern when adding inputs.
- Do not edit `_hardware-configuration.nix` (generated by `nixos-generate-config`) or bump `system.stateVersion` / `home.stateVersion` (26.05).
- Machine-specific values live in the host module (`modules/hosts/<host>/`): NVIDIA PRIME bus IDs, LUKS UUIDs, `nixos-hardware` module list, and mango monitor rules.
- Commit messages follow conventional style (`feat:`, `fix:`, `refactor:`).
